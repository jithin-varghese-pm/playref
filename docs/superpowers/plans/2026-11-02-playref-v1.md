# Playref v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Playref v1 as specified in `docs/superpowers/specs/2026-11-02-playref-v1-design.md`: a phone-first rules referee for Classic UNO with checked button answers, a three-step typed-question path (match, saved answer, AI) and a public accuracy score.

**Architecture:** A Vite + React + TypeScript single-page app served by Cloudflare Pages. Pages Functions (`functions/api/*`) are thin wrappers around pure, tested server logic in `server/`. Logic shared by the app, the server and the eval runner lives in `shared/`. Rules live in `rules/` and are compiled into `shared/generated/rules-data.ts` by `scripts/build-rules.mjs`, so every runtime (browser, Pages Functions, Vitest, Node eval script) reads the same data.

**Tech Stack:** Node 22, Vite 5, React 18, TypeScript 5, Vitest 2, Testing Library, Cloudflare Pages + Pages Functions, Workers AI (`@cf/meta/llama-3.3-70b-instruct-fp8-fast`, JSON mode), D1.

**Verified facts this plan relies on (Cloudflare docs via Context7, 2 Nov 2026):**
- JSON mode (`response_format: { type: "json_schema", json_schema }`) is supported by `@cf/meta/llama-3.3-70b-instruct-fp8-fast`; failures return the error "JSON Mode couldn't be met".
- Daily free allocation exhausted = error 3036, HTTP 429, "You have used up your daily free allocation of 10,000 neurons". Limits reset 00:00 UTC.
- Pages Functions get the AI binding as `context.env.AI` via `[ai] binding = "AI"` in `wrangler.toml`.
- Pricing: 70B fp8-fast = 26,668 neurons per M input tokens, 204,805 per M output tokens. At about 2,500 input and 200 output tokens per question, that is about 108 neurons, or about 90 AI questions a day.

**Rules source:** Mattel Classic UNO sheet GDJ85 (`rules/reference/GDJ85-Eng.pdf`, private, git-ignored). Link shown in the app: https://service.mattel.com/instruction_sheets/GDJ85-Eng.pdf

## File map

| File | Responsibility |
|---|---|
| `package.json`, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `index.html` | Tooling |
| `wrangler.toml` | Pages project config: AI binding, D1 binding, `AI_MODEL` var |
| `migrations/0001_init.sql` | D1 tables: `rate_hits`, `saved_answers`, `feedback` |
| `rules/uno-classic.md` | Rule cards (source of truth) |
| `rules/uno-classic-fights.json` | Known fights: 6 buttons + hidden ones, with match words |
| `scripts/build-rules.mjs` | Parses the two rules files into `shared/generated/rules-data.ts`, computes `RULES_VERSION` (hash) |
| `shared/types.ts` | `Verdict`, `RuleCard`, `Fight`, `Answer`, `AskResponse` |
| `shared/normalize.ts` | Lower-casing, punctuation, card-name synonyms |
| `shared/match.ts` | Known-fight matcher with a confidence threshold |
| `shared/rules.ts` | Accessors: `getFight`, `getCard`, `buttonFights`, `fightToAnswer` |
| `server/prompt.ts` | System prompt + JSON schema for the AI |
| `server/validate.ts` | Checks the AI reply; builds NOT SURE fallback |
| `server/scope.ts` | Detects "other UNO version" and "not UNO" questions |
| `server/store.ts` | D1 access: rate limit, saved answers, feedback |
| `server/ask.ts` | The ask pipeline: limit, match, saved, AI, validate, save |
| `functions/api/ask.ts`, `functions/api/feedback.ts` | Pages Functions wrappers |
| `src/main.tsx`, `src/App.tsx` | App shell and screen state |
| `src/screens/Home.tsx`, `Thinking.tsx`, `VerdictScreen.tsx`, `Accuracy.tsx` | Screens |
| `src/lib/api.ts`, `src/lib/share.ts` | Fetch calls and the share sheet |
| `src/styles.css` | Option A look + motion + reduced motion |
| `evals/questions.json`, `evals/run.mjs` | 50 test questions and the scorer (writes `public/accuracy.json`) |
| `tests/**` | Vitest tests |
